SEC-01 // OVERVIEW

Overview

sonicRadar is an ultrasonic scanning rig that behaves like a simplified sonar set. An HC-SR04 sensor is mounted on a servo and swept through 180°, taking a distance reading at each step.

The readings are streamed to a computer where a Processing IDE sketch draws the sweep as a radar display, so obstacles appear as blips at their measured range and angle. A buzzer connected to the board gives an immediate audible warning when something is close.

SEC-02 // PROBLEM & SOLUTION

Problem and solution

ISSUE
  • A single fixed sensor only knows what is directly in front of it — no sense of direction.
  • Raw distance numbers scrolling past are hard to interpret, especially while an object is moving.
  • An obstacle close to the rig needs warning immediately, not after someone reads a log.
APPROACH

Turn the problem into a scan: sweep the sensor across 180°, pair every distance reading with the angle it came from, and send the pairs out over serial.

Visualise those pairs as a radar sweep in Processing IDE, and add a buzzer that fires as soon as a reading drops below the near-object threshold.

SEC-03 // HOW IT WORKS

How it works

  1. 01 Sweep. The servo steps the HC-SR04 through 180°, pausing briefly at each angle so the sensor can settle.
  2. 02 Measure. At every step the sensor sends an ultrasonic pulse and times the echo to work out the distance to the nearest object.
  3. 03 Alert. If a reading falls inside the near-object range, the buzzer sounds so the warning does not depend on watching the screen.
  4. 04 Stream. Angle and distance are sent over the serial link as a pair, which is what makes the picture meaningful rather than just a number.
  5. 05 Visualise. The Processing IDE sketch plots each pair as a blip and animates the sweep, producing the radar-style display.

SEC-04 // KEY FEATURES

Key features

  • 180° scanning sweep driven by a single servo-mounted ultrasonic sensor.
  • Audible proximity warning from a buzzer for objects inside the near range.
  • Live radar-style visualisation in Processing IDE rather than a serial-only output.
  • Angle/distance pairing so each blip is placed at the correct bearing.
  • Low-cost hardware: one Arduino Uno, one HC-SR04, one servo, one buzzer.

SEC-07 // WHAT I LEARNED

What I learned

  • Sensor fusion at the smallest scale — pairing an angle with a distance is what turns two readings into one meaningful measurement.
  • Serial bandwidth sets the scan rate: the more data sent per step, the slower the sweep becomes.
  • Visualising sensor data in a separate tool made faults obvious immediately, which numbers on a serial monitor never did.
